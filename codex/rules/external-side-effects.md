# 外部副作用ルール

`implement` または実際に外部副作用を伴う操作を行う時に適用する。通常の `question` 応答には適用しない。

## 絶対に守ること（これだけは必ず）

- 外部サービスに対するコマンドを実行する前に、以下3点をユーザーに提示して承認を得る。承認なしで実行した時点で運用違反
  1. 対象（何に対して実行するか）
  2. 使用コマンド（そのまま実行可能な形で）
  3. 想定される副作用（read-onlyかどうかの根拠：公式ドキュメントURLまたは `--help` の該当箇所）
- 「read-only っぽいから大丈夫」という判断は禁止。公式ドキュメントまたは `--help` で副作用がないことを確認できない限り、副作用ありとして扱う

## 実行順序

1. まず1件の非機密・低影響な対象でコマンドを実行して結果を確認する
2. 期待通りの結果であることをユーザーに報告する
3. ユーザーの承認後に残りの対象へ拡大する
4. いきなり全件バッチ処理を流すのは禁止。1件目の確認を飛ばした時点で運用違反

## 実行後の確認チェックリスト

コマンド実行後、以下を全て確認してからユーザーに完了報告する：

- [ ] 機能的な結果が期待通りか
- [ ] 共有設定・公開状態が変わっていないか
- [ ] 権限が変わっていないか
- [ ] 更新者・更新日時が意図しない値になっていないか

1つでも確認できない項目があれば、「未確認の項目がある」とユーザーに明示する。

## 監査ログ

外部サービスに対してコマンドを実行したら、以下をユーザーへの報告に含める：
- 実行したコマンド（コピペ可能な形で）
- 実行時刻
- 対象の一覧

## 失敗時

- 確認不足で実行した場合は `運用違反` と明示する（`理解不足` や `想定外` とは言わない）
- 言い訳より先に事実関係を報告する：影響を受けた対象、実行コマンド、実行時刻

## 具体例

- 良い例： 外部コマンドで、初めて使うので、公式ドキュメントを確認。副作用の大きいコマンドだったため、コマンドの使用を停止し、使用しない方が良いと提案した。
- 悪い例： 外部コマンドで、初めて使うが、命名的にこういう挙動をするだろうと推測。実際に使用したところ、予期せぬ副作用がトラブルが発生して問題となった。
