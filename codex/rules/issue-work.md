# 自律開発ガイド

夜間の自律開発セッション向け。IssueをPickして実装・PRを出すサイクルを繰り返す。

## 絶対に守ること（これだけは必ず）

- `claude-code-proposal` ラベルのIssueには触らない。人間の承認待ちなので、Pickした時点で運用違反
- 既存テストを削除・スキップして通すのは禁止。テストが邪魔なら、そのIssueは「詰まった」扱いにして次へ進む
- 1 Issue = 1 PR。複数Issueを1つのPRにまとめない

## Issue Pickの手順

1. `ready` ラベルのついたIssueを一覧取得する
2. 優先度順（ラベルまたは番号の若い順）で1つ選ぶ
3. そのIssueに以下のコメントを投稿してから作業開始する：
   ```
   作業を開始します。
   方針：<変更するファイルと変更内容を箇条書き>
   ```
4. コメントなしで作業を始めるのは禁止

## 実装→PR

1. ブランチを切る：`feature/<issue番号>-<簡潔な説明>` or `fix/<issue番号>-<簡潔な説明>`
2. TDDサイクルで実装する（tdd.md参照）
3. 全テスト実行 → パス確認
4. lint実行 → パス確認
5. テスト・lintが両方パスしてからPRを作成する（片方でも落ちている状態でPRを出すのは禁止）
6. PRタイトル：`[Claude Code] #<issue番号> <Issueタイトル>`
7. PR本文に `Closes #<issue番号>` を必ず含める

## 詰まったときの手順

15分以上進捗がない場合、以下を実行して次のIssueに進む：

1. そのIssueに以下の形式でコメントを投稿する：
   ```
   ## 作業中断

   **詰まった箇所：**
   <ファイル名:行番号レベルで具体的に>

   **試したこと：**
   - <アプローチ1と結果>
   - <アプローチ2と結果>

   **次に試すべきこと（人間へ）：**
   <具体的な提案>
   ```
2. ブランチは削除せずそのまま残す
3. 次の`ready` Issueに進む

## やらないこと

- 大きな設計変更を独断で進める → Issueにコメントして次のIssueへ
- コード生成ツールの出力ファイルをコミットから除外する → 生成後のファイルも含める
