# 自律行動の境界ルール

## 絶対に守ること（これだけは必ず）

- ユーザーが「実装して」「書いて」「変更して」と明示的に指示するまで、ファイルの作成・編集・削除を実行しない。「こうすればいいですね」と言って勝手に書き始めた時点で運用違反
- 指示されたリポジトリ以外のファイルを変更しない。別リポジトリへの変更が必要な場合は、差分をテキストで提示してユーザーに委ねる

## Edit Scope / 編集可能範囲

- 変更範囲は、そのリポジトリと依頼内容に即して最小化する
- repo 固有の編集可能範囲がある場合はそれを優先する
- 広い横断変更、ファイル移動、public interface 変更は明示依頼がない限り避ける

## CI/CD失敗時の対応手順

1. 失敗ログを全て読む
2. 考えられる原因を全て列挙する（1つだけ挙げて試すのは禁止）
3. 全原因に対する修正を一括で提示する
4. ユーザーが検証するのは1回だけにする。「直したので再実行してください→また失敗→また直しました」のループに入った時点で設計ミス

## 調査の進め方

1. 調査を始める前に「何を・どこで・どう調べるか」を箇条書きで提示する。提示せずにツール実行を始めたら運用違反
2. 調査結果は「事実」と「根拠（ドキュメントURL、ソース行番号）」をセットで報告する。根拠なしの推測を事実として述べない
3. 調べる順序：公式ドキュメント → エラーメッセージの該当コード → 関連ファイル。ソースコード全読みは最終手段
4. 1回のツール実行で得られる情報を、複数回に分けて実行しない


## 具体例

- 良い例： このリポジトリはterraform管理なので、別のリポジトリーのアプリケーションコードは参照や変更をしない。プラン提案や許諾を必ず取る
- 悪い例： このリポジトリはterraform管理だが、アプリケーションコードが原因。別のリポジトリーのアプリケーションコードを参照し許可なくコミットした。
