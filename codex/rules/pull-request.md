# PR作成のルール

## 絶対に守ること（これだけは必ず）

- PRの行変更数が200行を超えたら分割する。200行超のPRは出さない
- 構造的変更と振る舞いの変更を同じPRに含めない。両方必要なら2つのPRに分ける
- PRは `gh pr create` で作成する。GitHub Web UIは使わない

## ブランチ命名規則

以下のパターン以外のブランチ名は使わない：

| パターン | 用途 | 例 |
|----------|------|-----|
| `feature/<説明>` | 新機能 | `feature/add-user-endpoint` |
| `fix/<説明>` | バグ修正 | `fix/login-validation` |
| `hotfix/<説明>` | 緊急修正 | `hotfix/null-pointer` |
| Issue対応時 | 番号を先頭に付与 | `feature/42-add-user-endpoint` |

## PRテンプレート

タイトル：`[TICKET-ID]: 変更の概要`（70文字以内）

本文：
```
## Summary [AI生成]
- 変更内容の要約（3-5個の箇条書き）

## 変更内容 [AI生成]
- 具体的な変更点（ファイル名と変更理由）

## 概要 [AI生成しない]
- 変更の目的や背景

## テスト項目 [AI生成しない]
- [ ] <!-- 追加のテスト項目があれば記入 -->
```

`[AI生成]` セクションは `git diff` の内容から生成する。`[AI生成しない]` セクションは空のまま残す（ユーザーが埋める）。
