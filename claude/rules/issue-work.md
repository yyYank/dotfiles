# Claude Code 自律開発ガイド

## 概要

このドキュメントは夜間の自律開発セッション向けのルールです。
IssueをPickして実装・PRを出すサイクルを繰り返します。

## 基本フロー

1. `ready` ラベルのついたIssueを優先度順にPickする
2. Issueにコメントで作業開始を宣言する
3. 実装する
4. PRを出してIssueにコメントを残す
5. 次のIssueへ

作業開始コメント例：
```
作業を開始します。
方針：<実装方針を簡潔に>
```

## Issue管理

- Pickする対象：`ready` ラベルがついているIssue
- `claude-code-proposal` ラベルのIssueは人間の承認待ちなので触らない
- 1つのIssueに対して1つのPRを原則とする

## 詰まったとき

実装中に行き詰まった場合は**次のIssueに進む**。
そのIssueに以下の形式でコメントを残す：

```
## 作業中断

**詰まった箇所：**
<何が問題かを具体的に>

**試したこと：**
- <アプローチ1>
- <アプローチ2>

**次に試すべきこと（人間へ）：**
<提案があれば>
```

ブランチはそのまま残しておく（削除しない）。

## PR規則

- ブランチ名：`claude-code/<issue番号>-<簡潔な説明>`（例：`claude-code/42-add-user-endpoint`）
- PRタイトル：`[Claude Code] #<issue番号> <Issueタイトル>`
- PRの説明には必ず対応IssueのCloses参照を入れる（例：`Closes #42`）
- テストとlintが通っていることを確認してからPRを出す
- テストが書けるものは必ず書く

## 品質基準

- テストがすべてパスすること
- lint がパスすること
- コード生成ツールを使う場合は生成後のファイルもコミットに含めること
- 手を抜かず、でも完璧主義にならない。動くことを優先する

## やらないこと

- 既存のテストを削除・スキップして通す
- `claude-code-proposal` ラベルのIssueへの着手
- 複数Issueをまとめて1つのPRにする
- 人間のレビューが必要そうな大きな設計変更を独断で進める（Issueにコメントして次へ）
