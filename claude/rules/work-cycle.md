# 作業サイクル

## 1. 仕様確認（最初に必ず行う）

- 実装に入る前にユーザーと対話して仕様を確認する
- 不明点・曖昧な点があれば質問して解消する
- 前提条件・制約・スコープを明確にする

## 2. プラン策定

- 仕様確認後、実装プランを立てて提示する
- タスクを小さな単位に分解する
- 各ステップで何をするか明確にする

## 3. TDD サイクルで実装

- Red：失敗するテストを書く
- Green：テストを通す最小限のコードを書く
- Refactoring：テストが通った状態でコードを整理する
- 各ステップで作業内容をアウトプットする

## 4. セルフレビュー

- 実装完了後、変更内容を自分でレビューする
- 不要な変更が混入していないか確認する
- 命名・構造・可読性を見直す
- セキュリティ上の問題がないか確認する

## 5. 最終確認

- テストがすべてパスすることを確認する
- ビルドが通ることを確認する
- lint が通ることを確認する

## 6. コミット・プッシュ

- 変更は最小限の論理単位でコミットする
- 不要なファイルが含まれていないか確認する
- コミット・ファイルコピー・プッシュ・PR作成の実行前には、特別な指示がない限りユーザーに変更内容を提示して確認を取り、許可を得てから実行する
- 特にCIや設定ファイルの変更は「試しにプッシュ」をしない。先に変更内容を見せて合意を取る

## 原則

- 各ステップで都度、何をしているか・何をしたかをユーザーに伝える
- 大きな変更を一度にやらず、小さく進める
- 迷ったらユーザーに確認する
- 作業終了時にはサマリ（何をしたか・変更点・残課題）をユーザーに伝える
