# flush

## トリガー

次のどちらかで、このスキルを実行する。

- ユーザーが「は？」「何言ってんの？」「意味不明」など、直前の回答を受け入れられないという反応を返したとき。
- ユーザーが /flush と打ったとき。

## 前提

AIの直前の回答に問題があった。過失はAIにある。ユーザーの理解力や質問の仕方のせいにしない。原因候補

- 回答が質問を取り違えている
- この会話中だけで通じるAI用語で書かれている
- 設計の筋が著しく悪い
- 回答が一転二転している
- 違反行動をしている

直前の回答の言い換えは同じ失敗を繰り返すので、行わない。

## 手順

1. 直前の回答を捨てる。その文面、構成、用語を再利用しない。謝罪は書く。言い訳はしない。
2. ユーザーの元の質問を読み直す。直前の回答ではなく、ユーザーが実際に書いた文を根拠にする。
3. 原因候補のどれにあたるかをユーザーに確認する。次の文面だけを出力して、ユーザーの回答を待つ。回答を受け取るまで手順4に進まない。

```
申し訳ありません。
どういった問題がありますでしょうか？

- 回答が質問を取り違えている
- この会話中だけで通じるAI用語で書かれている
- 設計の筋が著しく悪い
- 回答が一転二転している
- 違反行動をしている
```

4. ユーザーの回答を受け取ったら、選ばれた原因を直したうえで、次の形式だけを出力する。

```
質問の理解：ユーザーの質問を1文で言い直す。
答え：その質問への答えを1文で書く。
理由：答えを直接支える事実を最大2つ。なければ省略する。
```

5. 質問の意図や前提を確定できないときは、上の形式を出さず、不明な点を1つだけ質問する。

## 書き方の規則

- この会話を読んでいない人に通じる言葉で書く。
- 会話中に生まれた呼び名、略語、ラベルを使わない。使う必要がある専門用語には、その場で一言の説明を付ける。
- 完全な文で書く。主語と対象を省略しない。記号や矢印で文を代用しない。
- 1文に1つの事実だけを書く。
- 確認していないことは「推測」と明記する。分からないことは「分からない」と書く。
- 手順4の出力は全体で5行以内に収める。補足、注意書き、次の提案は書かない。

## 改善提案

同じ原因がこの会話の中で2回以上選ばれたときは、手順4の出力の後に、rules またはこのスキルへの改善提案を1文で足す。提案するだけで、自分では書き換えない。採用するかどうかはユーザーが決める。
