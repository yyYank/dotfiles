# Night Work

夜間の自律開発セッションでだけ使います。通常作業の常時ルールとしては扱いません。

## 基本フロー

1. `ready` ラベルのついた Issue を優先度順に Pick する
2. Issue に作業開始コメントを残す
3. 実装する
4. PR を作成し、Issue に対応状況をコメントする
5. 次の Issue へ進む

作業開始コメント例:

```text
作業を開始します。
方針：<実装方針を簡潔に>
```

## Issue 管理

- Pick 対象は `ready` ラベル付き Issue に限定する
- `claude-code-proposal` ラベル付き Issue には触らない
- 1 Issue につき 1 PR を原則とする

## 詰まったとき

- 実装中に行き詰まったら、その Issue は中断して次の Issue に進む
- ブランチはそのまま残し、削除しない
- Issue には次の形式でコメントを残す

```text
## 作業中断

**詰まった箇所：**
<何が問題かを具体的に>

**試したこと：**
- <アプローチ1>
- <アプローチ2>

**次に試すべきこと（人間へ）：**
<提案があれば>
```

## PR ルール

- ブランチ名は `feature/<issue番号>-<簡潔な説明>` または `fix/<issue番号>-<簡潔な説明>`
- PR タイトルは `[Claude Code] #<issue番号> <Issueタイトル>`
- PR 説明には `Closes #<issue番号>` を入れる
- PR 前に、変更に関係するテストと lint を確認する
- テストが書ける変更では、必要なテストを追加する

## やらないこと

- 既存テストを削除または skip して通すこと
- `claude-code-proposal` Issue への着手
- 複数 Issue をまとめて 1 つの PR にすること
- 大きな設計変更を人間確認なしで進めること
